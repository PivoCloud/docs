## Your apps

Every entry below links to the page that explains it in full.

- Deploy a Laravel, Node, Python or Go repository that has no Dockerfile. PivoCloud looks at your code, builds the image for you and runs it: [can I deploy without a Dockerfile](/apps/deploy-without-a-dockerfile).
- Start a Laravel app with nothing typed. PivoCloud creates its application key on the first deploy, and an attached PivoCloud PostgreSQL database is used without setting Laravel's database variables yourself: [can I deploy without a Dockerfile](/apps/deploy-without-a-dockerfile).
- Choose the port your app listens on with `Listen port` in the app's build settings, for an app built without a Dockerfile: [can I deploy without a Dockerfile](/apps/deploy-without-a-dockerfile).
- Choose the start command, the build command and the language version with files in your repository, such as a `Procfile`, `railpack.json`, `.nvmrc` or `.python-version`: [can I deploy without a Dockerfile](/apps/deploy-without-a-dockerfile).
- Stop or delete an app after you removed PivoCloud's access on GitHub. These no longer need GitHub, and the edit page now says `GitHub disconnected` when access is gone: [how do I connect GitHub to PivoCloud](/apps/connect-github).
- A top-up that brings a suspended app back is refunded if the app then fails to start: [credit and charges](/billing/credit-and-charges).
- See when your deploy is waiting its turn to build. It reads `Queued`, starts by itself, and its build time limit starts only when its build starts: [how do I deploy my first app](/apps/deploy).
