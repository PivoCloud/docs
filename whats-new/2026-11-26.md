## Redeploying your app

- When you redeploy a running app, the new version starts beside the one that is running. It takes over only once it has started and answers, so your visitors see no error during the switch: [when you redeploy a running app](/apps/deploy#when-you-redeploy-a-running-app).
- If the new version does not start, the version that was running keeps serving. The console, your AI agent and the `Deployments` tab tell you why in one sentence and show the previous version as live.

## Pushing to your deploy branch

- Every push to your app's deploy branch is built. A push made while a deploy of the same app is waiting or running is built as soon as that deploy ends, and several pushes in a row become one build of your latest commit. The waiting push shows in the `Deployments` tab: [when you push while a deploy is running](/apps/deploy#when-you-push-while-a-deploy-is-running).
- A push is built even when GitHub could not tell PivoCloud about it. PivoCloud checks your deploy branch every few minutes and builds a commit it has not seen, the same way as a push it was told about.

## Your app and its database

- If the database attached to your app is stopped or not ready, a deploy, a restart or a settings change is refused before your running app is touched, and the message names the database: [the database attached to the app is not running](/apps/troubleshooting#database_unavailable).
- Deleting a database detaches it from every app that uses it, and the delete confirmation lists those apps first. An app still linked to a database that was deleted earlier gets all its other settings, and you can remove that link from the app at any time: [when the attached database is stopped or deleted](/apps/environment-variables#when-the-attached-database-is-stopped-or-deleted).
